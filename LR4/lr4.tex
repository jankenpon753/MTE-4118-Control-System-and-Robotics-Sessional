\section*{Theory}
Forward kinematics computes the end‑effector pose from known joint variables. For a planar 2‑DOF manipulator with revolute joints \(\theta_1,\theta_2\) and link lengths \(L_1,L_2\) (Figure~\ref{fig:fwdk}),
\[
    x = L_1\cos\theta_1 + L_2\cos(\theta_1+\theta_2),\qquad
    y = L_1\sin\theta_1 + L_2\sin(\theta_1+\theta_2).
\]
Simscape Multibody is used for physics‑based simulation (rigid links and joints) while the Robotics System Toolbox builds a corresponding rigidBodyTree for analytic kinematics and cross‑validation \cite{Craig2005,Niku2001}.

The manipulator is a planar 2‑DOF serial robot with revolute joints $q_1,q_2$. Figures \ref{fig:2dof}--\ref{fig:testcase} show the assembly and an example snapshot.

Simscape implementation:
\begin{itemize}
    \item Links use \texttt{Solid} blocks (thin rectangular solids) and two serial \texttt{Revolute Joint} blocks.
    \item Joint inputs $(q_1,q_2)$ drive the model; \texttt{Joint Position Sensor} blocks provide measured angles $(q_{1m},q_{2m})$ for logging.
\end{itemize}

Verification:
\begin{itemize}
    \item Measured angles feed a MATLAB/Robotics System Toolbox routine that builds a \texttt{rigidBodyTree} (matching DH parameters) and computes the end‑effector pose $(x,y)$.
    \item The toolbox pose is compared with the Simscape pose to validate the forward kinematics.
\end{itemize}

\subsection*{Output Analysis}
\addcontentsline{toc}{subsection}{Output Analysis}
The snapshots (Figure~\ref{fig:snapshots}) show the manipulator following the planned configurations and agree with the forward‑kinematics model. The joint angle plot (Figure~\ref{fig:angles}) confirms the commanded timings and amplitudes for $q_1$ and $q_2$. Small deviations (millimetre scale) are attributed to numerical integration and approximate inertial/geometric properties and are within acceptable tolerances.

\section*{Discussion}
\addcontentsline{toc}{section}{Discussion}
The Simscape and rigidBodyTree results agree within millimetre‑scale tolerances across the tested configurations. Remaining discrepancies are mainly due to numerical integration, simplified inertial/visual geometry, and sensor logging quantisation. These effects can be mitigated by refining inertial parameters, increasing solver accuracy, and synchronising logging timestamps. Overall, the analytic forward‑kinematics implementation is validated against the physics‑based model for the examined workspace.

\section*{Conclusion}
\addcontentsline{toc}{section}{Conclusion}

The 2‑DOF manipulator was modelled in Simscape Multibody and represented as a rigidBodyTree in the Robotics System Toolbox. Analytic forward kinematics agreed with the Simscape results for the tested configurations; refining parameters and sensor fidelity is recommended to reduce remaining discrepancies.
